# cf-d1-moments · 极简朋友圈（Cloudflare 版）

照 [kingwrcy/moments](https://github.com/kingwrcy/moments) 的版面，在 Cloudflare 上自研重写的「朋友圈」式极简微博：封面 + 头像时间线、发动态、图片/视频九宫格、点赞评论，全部跑在 Cloudflare 免费额度里，零服务器、零依赖。

- 一个 **Worker**（原生 JavaScript，无框架、无构建）跑全部页面与接口
- **D1**（SQLite）存动态、评论、设置与密码；**R2** 存图片/视频/附件（经 Worker 代理读取，桶不公开）
- 一切配置只存 D1，重新部署不会冲掉密码

**当前版本 2.20.5**（版本号：增减功能进中段、修 bug 进尾段；页脚显示当前版本）

## 功能一览

- **发动态**：富文本 / Markdown 双模式；标题、标签、星标置顶（一星/两星/三星，三星最高）、定时发布、隐藏；图片视频九宫格、任意文件（经计数下载通道下发，附件卡片上显示已被下载的次数）、B 站/YouTube/网易云/豆瓣/链接卡片、抖音嵌入；上传图片自动压缩；附件可点「插入正文」放到正文任意指定位置（图文混排），不指定位置的默认排在正文末尾
- **可见范围**（逐条可选）：公开 / 观看密码 / 回复后可见（正文或附件）/ 仅注册用户可评论 / 仅注册用户可见
- **全站密码门**（可选）：访客输对密码才能浏览全站，30 天免输
- **互动**：点赞（IP 去重）；评论（回复、表情、字数上限注册用户/站长 80 字、游客 50 字）；首页点 💬 原地弹评论框
- **访客账号**（可开关）：自助注册（图形验证码，注册时随机绑定一个内置头像、不可修改，投稿与评论旁都会显示）；登录后用用户名评论、免验证码；游客免填昵称、只填验证码，随机显示「游客XXX」；评论可勾「仅管理员可见」（别人只看到橙色「隐藏评论」占位）；另有开关可开放注册用户发动态（简化表单：只有标题、正文、上传图片/压缩包≤500KB，没有标签栏，没有置顶/隐藏/门控等管理员选项，署名作者本人，只能改删自己的）；登录用户工具栏有铃铛通知提醒（带未读数角标）：评论被回复、或自己发的动态被评论时收到通知，待审评论在审核通过后补发
- **私信**：登录用户点评论区或动态上的用户名即可发私信（普通用户每封要过图形验证码，另有频率限制防骚扰），工具栏信封图标点开是消息中心：私信与评论通知分板块显示，共用一个未读角标；站长在前台同样有信封与角标：有人私信、评论站长动态或回复站长时都会提醒，点开是站长的消息中心；私信对话与通知都可删除（通知可逐条删或一键清空，删对话只删自己一侧、对方无感）
- **论坛模式**（后台开关）：首页与标签页把每条动态收拢成论坛式的一行标题（无标题时用正文首行顶替），带作者、时间、点赞与评论数；点开就地展开完整动态，同时只保持一条展开
- **评论治理**：先审后显可切换；六道防垃圾（蜜罐、过快提交、关键词、链接数、重复、频率），命中进垃圾箱
- **后台**：动态管理、评论审核、注册用户管理（看最后登录的设备/系统/IP/地址，可禁用、删除）、站点设置、完整备份（ZIP）与恢复；登录防爆破
- **其它**：跑马灯公告、暗黑模式（浅色/暗夜的框架底色都铺淡淡的线条涂鸦图案：星星、爱心、云朵等）、友链、RSS、页脚建站天数/到访人数/用量显示

## 部署前先了解：它由什么组成

整个站点只用 Cloudflare 的三样东西：Worker（页面与接口）、D1（数据）、R2（文件），组件与名字见上方「架构」表。

**两个重要特性，先知道：**

- **所有配置都只存 D1**（包括管理员密码哈希），不在代码和环境变量里。所以重新部署代码**永远不会**冲掉你的密码和设置。
- **数据表是程序自动建的**：部署完成后第一次访问首页，Worker 会自动把所有表建好，不需要你手动执行任何 SQL（唯一例外是第 6 步设置管理员密码要往表里写一行）。

## 准备工作

| 需要的东西 | 说明 |
| --- | --- |

## 第一步：拿到代码

```bash
git clone https://github.com/sandeli/cf-d1-moments.git
cd cf-d1-moments
```

没有 git 也可以在 GitHub 仓库页点 **Code → Download ZIP** 下载解压。

> 如果你走「网页导入仓库」方式部署（第 6 步方式 B），代码可以不下载到本地，直接把仓库 fork 到自己的 GitHub 账号即可。

## 第二步：创建 D1 数据库

**网页操作：**

1. 登录 Cloudflare 控制台，左侧菜单进 **存储和数据库 → D1 SQL 数据库**
2. 点 **创建数据库**，名字填 `cf-d1-moments-db`，点创建
3. 创建完在数据库详情页找到 **数据库 ID**（一串 UUID，形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`），**复制记下**，第 6 步要用

**或命令行：**

```bash
npx wrangler d1 create cf-d1-moments-db
```

输出里会直接给出 `database_id`，同样记下。

⚠️ 注意：**不要**在这里建任何表。表由程序首次访问时自动创建；`schema.sql` 只是给你看的结构参考。

## 第三步：创建 R2 存储桶

1. 控制台左侧进 **R2 对象存储**（第一次进按提示开通）
2. 点 **创建存储桶**，名字填 `cf-d1-moments-media`，位置选自动即可，点创建
3. **不要**给桶开公开访问（不要绑 r2.dev 公开域名、不要设公开策略）——所有文件都由 Worker 代理下发，桶保持私有才安全

## 第四步：填写配置并部署 Worker

### 6.1 改配置文件

用任意文本编辑器打开项目里的 `wrangler.jsonc`，把 `database_id` 的占位值换成第 4 步记下的真实 ID：

```jsonc
{
  "name": "cf-d1-moments",              // Worker 名（= 站点子域名的一部分，改名三处同步）
  "main": "src/index.js",               // 入口文件，不要动
  "compatibility_date": "2025-01-01",   // 不要动
  "d1_databases": [
    {
      "binding": "DB",                  // 绑定名必须叫 DB，写错全站报错
      "database_name": "cf-d1-moments-db",
      "database_id": "<换成你的数据库 ID>"
    }
  ],
  "r2_buckets": [
    {
      "binding": "MEDIA",               // 绑定名必须叫 MEDIA
      "bucket_name": "cf-d1-moments-media"
    }
  ]
}
```

如果你在第 4/5 步用了别的名字，把这里的 `database_name`、`bucket_name`、`name` 一并改成你的名字，三处保持一致即可。

### 6.2 部署（二选一）

**方式 A：命令行（推荐，之后升级也最方便）**

```bash
npx wrangler login     # 第一次执行会弹浏览器，在网页上点授权
npx wrangler deploy    # 上传代码并绑定 D1/R2，一条命令完成
```

部署成功会输出站点地址，形如 `https://cf-d1-moments.<你的子域>.workers.dev`。

**方式 B：网页导入 GitHub 仓库（不用装 Node）**

1. 先把仓库 fork 到你自己的 GitHub 账号（或把代码推到你自己的仓库），并在仓库里把 `wrangler.jsonc` 的 `database_id` 改好提交
2. Cloudflare 控制台 → **计算（Workers）→ Workers 和 Pages → 创建 → 导入存储库**，授权并选择这个仓库
3. 构建设置里：**构建命令留空**，**部署命令填 `npx wrangler deploy`**
4. 点部署，等待构建完成，得到同样的 `workers.dev` 地址

### 6.3 验证部署成功

浏览器打开站点地址：能看到一个空的朋友圈首页（封面区、站名「我的朋友圈」、暂无动态）就是部署成功，并且**这第一次打开已经把数据库的表都建好了**（第 6 步的前提）。

> 如果打开报 1101 错误：多半是 workers.dev 的平台偶发故障，不是你的问题，等几分钟或绑自定义域名（下一步）后一般就正常。

## 第五步：（可选）绑定自己的域名

1. 前提：你的域名 DNS 已托管在 Cloudflare（域名在别的注册商也可以，把 NS 改到 Cloudflare 即可）
2. 控制台进这个 Worker → **设置 → 域和路由 → 添加 → 自定义域**
3. 输入你想用的域名，如 `blog.example.com`，确认添加，Cloudflare 会自动配好 DNS 和 HTTPS 证书
4. 等 1~2 分钟证书生效，用新域名打开验证

> 绑了自定义域名后，日常就用新域名访问；`workers.dev` 地址仍然有效，可作备用。

## 第六步：初始化管理员密码（关键一步）

管理员密码不写在代码里，而是通过**一次性令牌**在数据库里初始化。整个过程做一次即可（忘记密码时也用同一套办法重设，见本节末尾）。

### 8.1 先确认已经打开过一次首页

没打开过首页，数据库里还没有 settings 表，后面的 SQL 会报错。先访问一次站点首页再回来。

### 8.2 想一个令牌并算它的 SHA-256

令牌就是一句你自己定的口令，例如 `my-secret-token-123`（建议长一点、带数字符号）。算出它的 **SHA-256 小写十六进制**值：

- **Mac / Linux 终端**：`printf 'my-secret-token-123' | sha256sum`
- **Windows PowerShell**：
  ```powershell
  $s='my-secret-token-123'; $h=[System.Security.Cryptography.SHA256]::Create().ComputeHash([System.Text.Encoding]::UTF8.GetBytes($s)); -join ($h | ForEach-Object { $_.ToString('x2') })
  ```
- 也可以用在线 SHA-256 工具（令牌是你自定的临时口令，用完即废，在线算可接受；介意的话用上面本地方法）

### 8.3 把令牌哈希写进数据库

控制台 → **存储和数据库 → D1** → 点你的库 → **控制台（Console）** 标签，在 SQL 输入框执行下面两行（第二行的数字 = 当前 unix 时间戳 + 172800，即 48 小时内有效；当前时间戳可搜「unix 时间戳」在线获取）：

```sql
INSERT INTO settings (key, value) VALUES ('setup_token_hash', '<刚才算出的 SHA-256>');
INSERT INTO settings (key, value) VALUES ('setup_expires', '<当前 unix 秒 + 172800>');
```

> 如果提示这两行已存在（重复初始化场景），把 `INSERT INTO` 换成 `INSERT OR REPLACE INTO` 再执行。

### 8.4 打开初始化页面设置密码

浏览器打开：

```
https://<你的域名>/admin/setup?token=<redacted>
```

页面会让你输入两次管理员密码，提交后：密码以哈希形式存入 D1，令牌立即作废，这个链接以后再打开也没用了。

之后进后台就是 `https://<你的域名>/admin`，用刚设的密码登录（后台登录只有密码一个框，没有用户名）。

### 8.5 忘记密码怎么办

在 D1 控制台执行下面一句清空密码，然后重复 8.2~8.4 重新初始化即可，原有动态、评论、设置都不受影响：

```sql
UPDATE settings SET value = '' WHERE key = 'admin_password_hash';
```

## 第七步：进后台把站点设置好

登录 `/admin` 后，先到 **站点设置** 页逐项过一遍（保存即生效，不用重新部署）：

| 设置项 | 说明 |
| --- | --- |
| 站点名称 | 浏览器标题与页眉站名 |
| 昵称 | 显示在封面和每条动态上的名字（评论区里它会被标金色「站长」徽章） |
| 个性签名 | 封面下方那一行小字 |
| 公告（跑马灯） | 首页顶部横向滚动的一句话，留空不显示 |
| 头像图片 | 点「上传替换」直接传图（自动存进 R2），也可以填一个图片地址 |
| 封面图片 | 同上；页眉大图 |
| **封面来源** | 二选一：**自己上传**（用上面那张封面图）/ **跟随 Bing 每日壁纸**（每天自动换一张必应壁纸，服务器每天取一次并缓存，手机上自动使用竖版图）。选了 Bing 后手动封面图暂时不生效，切回来即可恢复 |
| 开启评论 | 关掉后全站不能评论 |
| 开放游客注册 | 关掉后访客只能以随机「游客XXX」身份评论，不能注册账号 |
| 开放注册用户发动态 | 开启后注册用户能发自己的动态（简化表单：标题/正文/传图，只能管自己的） |
| 论坛模式 | 开启后首页与标签页把每条动态收成一行标题，点开才展开全文（像论坛帖子列表） |
| 评论是否审核 | **先审后显**：评论进后台等你通过才显示 / **直接显示**：正常评论立即显示（垃圾评论照样会被拦） |
| 防垃圾关键词 | 逗号分隔，评论或昵称命中就进垃圾箱，可随时增删 |
| 全站访问密码 | 设了之后访客要先输密码才能浏览全站（输对一次 30 天免输），留空关闭 |
| 建站日期 | 页脚「建站第 N 天」的起算日 |
| 友情链接 | 每行一条，格式在设置页有示例 |

**建议的上手顺序**：先改站名/昵称/签名 → 传头像和封面（或开 Bing 每日壁纸）→ 评论审核先用「先审后显」跑几天，熟悉了再考虑直显 → 回到首页发第一条动态试试。

### 发第一条动态

后台 → **动态 → 写新动态**（前台首页工具栏也有发布入口）：

- 正文支持富文本编辑器（加粗、颜色、字号、链接、对齐）与 Markdown 两种写法
- 图片/视频在下方上传区添加，排成九宫格（1 张大图、2 张两列、4 张 2×2、5 张 3+2、6 张 3×2、9 张整九宫格）；任意文件也能传，显示为可下载的附件卡片（带下载次数）
- 附件点「插入正文」可以放到正文任意位置做图文混排，不插的默认排正文末尾
- 可选：标题、标签（逗号分隔）、星标置顶（一星/两星/三星，三星最高）、定时发布、隐藏
- 可见性进阶（逐条设置）：观看密码（输密码才能看这条）、回复后可见（必须直接评论这条动态才解锁正文/附件；开了评论审核时，要等审核通过才解锁）、仅注册用户可评论、仅注册用户可见

| 看谁给我发了私信/通知 | 前台工具栏信封图标（消息中心，私信与通知分板块，角标是两者未读合计） |
| 改站点一切设置 | 后台 → 站点设置 |
| 备份 / 恢复 | 后台 → 完整备份 / 恢复备份 |

前台小知识（可以告诉你的访客）：

- 评论时游客不用填昵称，系统随机给「游客XXX」并只需过图形验证码；注册登录后评论免验证码
- 点评论区里的用户名可以发私信（站长和注册用户可达；纯游客名字点不动）
- 动态作者和站长在评论区有专属徽章（蓝色「作者」/金色「站长」）
- 被系统判为垃圾的评论会在评论区显示为一行灰色「无效评论待修改」，原内容只有站长在后台能看到
- 键盘乱打的无意义评论（如 `hxhxhhxh`）会被直接拦下不入库，正常短评（顶、666、yyds）不受影响

## 升级更新（改版后如何重新上线）

代码更新不会影响任何数据（数据全在 D1/R2 里），流程就三步：

**命令行方式：**

```bash
cd cf-d1-moments
git pull            # 或把新代码覆盖进来
npx wrangler deploy
```

**网页导入方式**：把新代码推到仓库，Cloudflare 会自动重新构建部署；或进 Worker 页点「部署」手动触发一次。

注意三点：

1. `wrangler.jsonc` 里的 `database_id` 别被示例占位值覆盖回去——升级时保留你自己那份配置
2. 数据库表结构是**向后兼容自动升级**的（程序启动时自动补新表新列），不需要手动跑迁移 SQL
3. 页脚右下角显示当前版本（如 `Powered by v2.20.5 @TaoGe`），升级后刷新页面核对版本号变了即成功

版本号规则（供自己改版时参考）：三段式 `主.中.尾`——增减功能递增中段、尾段归零；只修 bug 递增尾段。版本号写在 `src/db.js` 的 `VERSION` 常量里，是全站唯一出处。

## 备份与恢复

**备份**：后台 → **完整备份**，一键导出 ZIP（包含全部动态、评论、用户、设置的数据库导出 + R2 里的媒体文件）。建议每次大改版前、以及定期（如每月）各备一份，下载后存到与 Cloudflare 无关的地方（如本地电脑、网盘）。

**恢复**：后台 → **恢复备份**，上传备份 ZIP 导入。恢复会覆盖当前数据，操作前系统会再次要求确认；**恢复前请先把当前状态也备份一份**，防止导错包。

**额外保险（可选）**：D1 本身支持在控制台 **设置 → 时间点恢复（Time Travel）** 回滚到过去某个时间点（免费版保留天数有限，出大事时先看这里）。

## 免费额度与注意事项

免费版主要额度（**注意：都是整个 Cloudflare 账号共享，不是单个站点独享**）：

| 项目 | 免费额度 | 重置 |
| --- | --- | --- |
| Workers 请求 | 10 万次/天 | 每日 UTC 00:00（北京时间 08:00） |
| D1 行读取 | 500 万行/天 | 同上 |
| D1 行写入 | 10 万行/天 | 同上 |
| D1 存储 | 5 GB（全账号） | — |
| R2 存储 | 10 GB | — |
| R2 读操作 | 1000 万次/月 | 按月 |
| R2 出口流量 | 免费 | — |

个人朋友圈的日常量级离这些上限非常远，但有一条血泪教训值得写在这里：

> ⚠️ **D1 的读写额度是同账号下所有数据库共享的。** 如果你在同一个 Cloudflare 账号里还跑了别的项目，只要其中任何一个项目出现「全表扫描」式的查询（比如每来一个请求就把整张表扫一遍），一天之内就能把 500 万行读取额度烧光，**连带这个朋友圈一起报 500 错误**。排查方法是到 Cloudflare 的 GraphQL 分析接口按数据库看 `sum(rowsRead)`，找到烧额度的那个库去修它的查询（加索引、加缓存），而不是给朋友圈充值。

页脚用量显示：

- 「存储已用 x%」：按 R2 免费 10 GB 换算，开箱即有
- 「今日请求已用 x%」：需要一个外部定时任务（每 15 分钟左右）把全账号今日请求数写进 D1 的 `settings` 表 `acct_usage` 键（JSON 格式 `{"n": 请求数, "t": unix秒}`）。仓库里的 `tools_acct_usage.py` 是参考实现，填入自己的账号信息后挂到任意定时器（cron、GitHub Actions 等）即可，不配也不影响其他功能

## 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 打开站点报 **1101** | workers.dev 平台偶发故障，与你的部署无关；等平台恢复，或改用绑定的自定义域名访问，一般不受影响 |
| 评论提交了但前台不显示 | ① 开了「先审后显」→ 去后台评论审核点通过；② 被防垃圾拦下 → 在评论审核的「垃圾留言」里能找到，误判可点通过放行 |
| 自己发的评论变成「无效评论待修改」 | 命中了防垃圾规则（关键词/链接过多/重复/过频等）被判垃圾：访客看到的是占位文字，你在后台垃圾箱里能看到原文；调整设置里的防垃圾关键词可减少误判 |
| 初始化页面提示令牌不对/已过期 | 依次检查：SHA-256 算的是令牌**原文**（不要带引号空格）；`setup_expires` 是 unix **秒**且在 48 小时内；执行 SQL 前已经打开过一次首页（表已建好）；域名和令牌不要拼错 |
| 登录后台提示密码错误 / 被锁 | 密码只存哈希、无法找回查看；多次输错会触发登录防爆破短时锁定，等一会儿再试；实在想不起来按 8.5 清空重设 |
| 图片/视频打不开 | 检查 `wrangler.jsonc` 里 R2 绑定名是 `MEDIA`、桶名与控制台一致；桶不要开公开访问（由 Worker 代理，开了反而可能冲突） |
| 头像/封面不显示 | 在后台设置里重新上传一次；若用地址模式，确认地址是 https 且能公开打开 |
| Bing 每日壁纸封面迟迟不出来 | 它是服务器每天取一次再缓存：每天的第一位访客会等服务器取图（几秒），之后全天都是缓存秒出；若长时间不出，多半是上游每日一图服务异常，切回「自己上传」即可，页面其他功能不受影响 |
| 站点突然全站 500，提示 D1 超限 | 多半是同账号其他项目烧光了共享的 D1 额度（见第 13 节的警告），等北京时间早上 8 点额度重置自动恢复，或先去把烧额度的项目查询修好 |
| 注册用户说收不到/看不到通知 | 通知在前台工具栏的铃铛/信封里，打开消息中心即全部标已读；待审评论的通知要等审核通过后才补发，这是设计如此 |
| 改了代码部署后没变化 | 先强刷（Ctrl+F5）排除浏览器缓存；再核对页脚版本号是否更新；还没变多半是部署没成功或 `database_id` 被占位值覆盖导致绑错了库 |

## 安全须知

1. **管理员密码只存 D1 的哈希**，代码仓库里永远不要出现真实密码、真实令牌；初始化令牌用完即废，教程/截图里不要晒出未使用的令牌
2. `wrangler.jsonc` 里的数据库 ID 不是秘密，但如果你的仓库要公开，建议仍用占位值、真实 ID 只放本地副本，避免给爬虫提供账号结构信息
3. R2 桶保持私有是底线：所有文件经 Worker 的 `/media/` 通道下发才有权限与计数控制
4. 后台地址就是 `/admin`，靠密码 + 登录防爆破保护；密码请设长一点，不要和其他网站共用
5. 有访客注册的站点，记得定期看一眼后台「注册用户」和「评论审核」，禁用明显是广告机器人的账号
